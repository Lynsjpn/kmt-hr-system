# KMT 人事管理システム（クラウド版）

登録支援機関（人材紹介・特定技能）向けの人事管理システム。
人事情報・労務書類チェックリスト（入社前〜退職後）・評価（MBO）・KPI・社内資産を一元管理します。

主な機能:
- **ユーザー管理タブ**: 利用者の追加と権限レベル（ゲスト／社員／管理者／全体管理）の変更（全体管理者のみ）
- **タレントタブ**（カオナビ型プロファイルブック）: イニシャルアバターのカード一覧・3段階ビュー切替（小/中/大）・部署/国籍/ステータス絞り込み・大ビューではスキルレーダーと最新評価ランクを表示
- **スキル管理タブ**（カオナビ型スキルマップ）: 6カテゴリ23項目の初期テンプレート（編集可）・5段階レベル・社員×スキルのマップ・個人レーダーチャート・組織サマリー（担い手不足スキルの検出）
- **評価管理の進捗ダッシュボード**: ステータス別進捗バー・未確定者一覧・ランク分布（管理者以上）
- **こころの健康タブ**: 厚労省「職業性ストレス簡易調査票」57項目＋新職業性ストレス簡易調査票からの選抜12項目のセルフチェック（単純合計法で自動採点・下位尺度の傾向表示）、本人のセルフケア、会社に求める対応（職場環境改善のためのヒント集6領域＋就業上の措置）を1本で収集。**個人結果を見られるのは本人と「メンタル担当」だけ**で、管理者・全体管理でも見られない（RLSで強制）。管理者は5名以上のときだけ集計値を閲覧できる
- 在留期限・取次者証・契約終了・試用期間の自動アラート
- **手続きガイドタブ**: 採用→入社→在職→退職→退職後の労務手続きチェックリスト（法定期限つき、2026年7月版）
- **書類テンプレート**: 従業員詳細の「📄書類作成」から、内定通知書・労働条件通知書兼雇用契約書・誓約書・身元保証書・在職証明書・貸与物返却確認書・退職関係書類など10種を本人情報入りで出力（画面上で編集→印刷/PDF）
- 詳細な運用ガイドは Drive フォルダの「労務管理ガイドブック2026.md」を参照

- **フロントエンド**: 単一の `index.html`（依存なし・GitHub Pages でホスト可能）
- **バックエンド**: Supabase（東京リージョン / プロジェクト `kmt-hr-system`）
  - PostgreSQL + Row Level Security（`allowed_users` に登録されたメールのみアクセス可）
  - Supabase Auth（メール＋パスワード）

## 使い方

1. ブラウザで `index.html`（または GitHub Pages の URL）を開く
2. 初回のみ「新規登録」でアカウント作成（メールは `allowed_users` に登録済みであること）→ 確認メールのリンクをクリック
   - パスワードは**利用者自身が新規登録時に設定**します（システム側の初期パスワードはありません）
3. ログインして利用開始

### パスワードを忘れたとき

ログイン画面の **「パスワードを忘れた方」** → メールアドレスを入力 → 届いたメールのリンクを開くと、新しいパスワードを設定する画面が出ます。設定するとそのままログインします。

- リンクの戻り先は、そのとき開いていたURLです。**Supabase → Authentication → URL Configuration の Site URL / Redirect URLs に公開URL（GitHub Pages のアドレス）が入っている必要があります。** 入っていないとリンクが別の場所へ飛びます。
- リンクには有効期限があります。切れていたら「設定に失敗しました」と出るので、もう一度送り直してください。
- 未登録のメールアドレスを入れても「送信しました」と表示されます（誰が登録済みかを外部に知られないため）。実際にメールは届きません。
- どうしても解決しないときは、Supabase ダッシュボード → Authentication → Users → 該当ユーザー → Send password recovery からも送れます。

## 公開・更新（GitHub Pages）

| 操作 | コマンド |
|---|---|
| 初回公開（リポジトリ作成＋Pages有効化） | `.\publish-to-github.ps1` |
| 変更をネットに反映（コミット＋push） | `.\sync.ps1` または `.\sync.ps1 "変更内容"` |

- 初回のみ GitHub CLI のインストールとブラウザでの GitHub ログインが必要です。
- 無料プランで GitHub Pages を使うため、リポジトリは **public** で作成します。
  従業員の個人データは Supabase 側にあり、リポジトリには含まれません（公開されるのはアプリのコードのみ）。
- **入力したデータは Supabase（東京リージョン）に即時保存されます。** GitHub への push はアプリ本体（`index.html`）の更新用で、業務データの保存とは無関係です。

## データを Supabase 側から直接入力する

Supabase ダッシュボード → Table Editor で以下のテーブルを直接編集できます:

| テーブル | 内容 |
|---|---|
| `employees` | 従業員マスタ（在留資格・パスポート等を含む） |
| `employee_docs` | 従業員×書類のステータス |
| `doc_templates` | 書類マスタ（入社前/入社時/在職中/退職時/退職後） |
| `evaluations` | 評価シート（goals は JSON） |
| `kpis` | KPI（records は JSON） |
| `assets` | 社内資産・貸与管理 |
| `departments` | 部署マスタ |
| `allowed_users` | ログイン許可メール＋権限レベル（`role`）・氏名（`display_name`）・メンタル担当（`mh_staff`） |
| `mental_checks` | こころの健康セルフチェックの回答（**本人とメンタル担当のみ閲覧可**） |
| `mental_followups` | 上記への対応記録（**メンタル担当のみ。本人にも見えない**） |

## 権限レベル（ユーザー管理タブ）

| レベル | できること |
|---|---|
| ゲスト | 手続きガイドのみ閲覧。従業員の個人情報は一切表示されない |
| 社員 | 自分自身の人事情報・書類・評価のみ閲覧（編集不可）。従業員マスタの「メールアドレス」欄がログインメールと一致するレコードで判定 |
| 管理者 | 全従業員の情報を閲覧・編集。ユーザー管理・全データ削除・JSON取込は不可 |
| 全体管理 | すべての操作＋利用ユーザーの追加・権限変更 |

- 判定は画面側とサーバー側（Supabase の RLS）の二重で行います。データベース一式（テーブル・RLS・
  新規登録制限トリガー・最初の全体管理者）は `supabase-setup.sql` にまとまっています（再実行可）。
- 自分自身の権限変更・削除、および最後の「全体管理」の変更・削除はできません（ロックアウト防止）。

### メンタル担当（`mh_staff`）— 権限レベルとは別の軸

こころの健康タブの**個人結果を見られる担当者**を指定するチェックボックスです（ユーザー管理タブ、全体管理者のみ変更可）。

- **解雇・昇進・異動に直接の権限を持つ人には付けないでください。** 法定ストレスチェックでも、人事権を持つ者は実施事務従事者になれません。健康情報と人事権を分離するための設計です。
- 管理者・全体管理であっても、このフラグが無ければ `mental_checks` は1行も返りません（Supabase の RLS で強制）。
- 管理者は `mental_summary()` 経由の集計値のみ取得できます。回答者が5名未満のときは個人が特定できるため、関数側で中身を返しません。
- 対応記録（`mental_followups`）はメンタル担当のみ。本人からも見えません。
- テーブル・RLS・集計関数は `supabase-mental-health.sql`（単体で流せます／`supabase-setup.sql` にも同内容が入っています）。
- 名前を出したくない人向けには、ログイン不要の配布用HTMLフォーム（Driveの「メンタルヘルス調査2026」フォルダ）＋ファイル提出を併用します。運用ルールと社内案内文は同フォルダの `01_実施要領と社内案内文.md` を参照してください。

## セキュリティ

- `index.html` 内のキーは **publishable key**（公開前提のキー）。データ保護は RLS が担います。
- **新規登録は `allowed_users` に登録済みのメールのみ**（DBトリガー `enforce_allowed_signup_trg` が部外者の登録を拒否）。
  社員を追加するときは、先に「ユーザー管理」タブでメールと権限レベルを登録してから本人に新規登録してもらいます。
- Supabase Auth の **「Confirm email」は絶対に無効化しないこと**。無効にすると、メールアドレスを知っている第三者が
  そのアドレスで登録できてしまい、全データにアクセスされます。
- マイナンバー（個人番号）そのものは入力しない運用としてください。
- 利用者の追加/削除・権限変更はアプリの「ユーザー管理」タブから行えます（全体管理者のみ）。
